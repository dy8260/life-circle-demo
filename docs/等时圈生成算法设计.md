# 等时圈生成算法设计

> 本文档说明等时圈如何基于路网计算可达范围，并覆盖等时圈可视化、空间插值与多人群扩展的实现。
> 实现位于 `js/isochrone.js`，配套路网绕行系数 λ 标定位于 `js/gap.js`，多人群扩展位于 `js/dashboard.js`。

## 1. 目标与定义

**15 分钟步行等时圈**：以用户给定的社区中心点出发，在真实路网下步行 15 分钟所能到达的所有区域的并集，用多边形近似表示。

主分析人群默认按成年人 80 m/min 计，目标弧长 = 80 × 15 = **1200 m**。

**为什么不是圆形辐射？**
- 真实路网（封闭小区、河流、立交、单行道）使步行可达区呈不规则形状；
- 圆形辐射要么高估（纳入穿墙/跨河到不了的区域），要么低估（直角绕行被压扁）；
- 多花几秒换来「真实路网」等时圈，对生活圈体检的可信度至关重要。

## 2. 算法流程（`Isochrone.build`）

```
输入：中心点 center，目标时间 15min
参数：sampleCount=16, walkSpeed=80m/min, walkMinutes=15, farDistance=1800m, routeConcurrency=6

1) 方向采样
   for i in 0..sampleCount-1:
       bearing = i × 360/sampleCount        // 每 22.5° 一个方向
       farPt   = Util.destination(center, farDistance, bearing)  // 取 >15min 的远点，留冗余

2) 并发取真实路网路径（核心）
   samples = Util.pmap(directions, _walkOne, routeConcurrency)
       _walkOne(start, end, targetDist, bearing):
           route = WalkingRoute(map, {renderOptions:{map:null,...}})
           route.search(start, end)          // 起点/终点须是 Point 实例
           取回路径点串 pts（防御式兼容多种返回形态）
           同时保留完整路径 pts → fullPaths[i]   // ← 多人群等时圈的输入，见 §5

3) 弧长插值边界点
   boundary = Util.pointAtDistance(pts, targetDist)   // 沿路径累加距离，线性插值

4) 退化兜底
   若 WalkingRoute 超时(6s)或失败 → boundary = Util.destination(center, targetDist, bearing)
   （按方位角直线远点，保证 16 点始终齐全）

返回：samples（每个方向一个边界点）+ area（多边形面积）+ fullPaths（完整路径）
```

## 3. 关键实现细节

### 3.1 方向采样
- 均匀 16 方向覆盖 360°，每方向独立远点，避免方向偏置。
- 远点 `farDistance = 速度 × 时长 × 1.5`（默认 1800 m），确保路径一定越过目标弧长，插值点落在路径中段而非末端。

### 3.2 真实路网路径（`_walkOne`）
- 调用地图步行路径规划服务，`renderOptions.map=null` 表示只取数据不画线（轻量）。
- **参数分级降级**：部分 GL 版本不接受 `map:null`，故准备两套 `opts` 依次尝试。
- **回调兼容**：除 `onSearchComplete` 外，兼容部分版本只触发 `setSearchCompleteCallback` 的情况。
- **6s 超时护栏**：到点即退化为直线远点，绝不卡死体检。

### 3.3 路径点提取（`extractPath`）
不同版本取路径的调用链不一致，做防御式兼容：
```
results.getPlan(0).getRoute(0).getPath()      // GL 官方
route.getPlan(0).getRoute(0).getPath()        // 经典版
route.getResults().getPlan(0)...getPath()     // 部分版本
results.getPlan(0).getPath()                  // 简化
route.getPlan(0).getPath()
```
过滤空项并统一为 `{lng,lat}` 字面量，长度 >1 才采用。

### 3.4 弧长插值（`Util.pointAtDistance`）
沿路径逐段累加 Haversine 距离，累计达 `targetDist` 时在当前段内按比例线性插值出边界点；全程不足则取末端。保证边界点严格落在「步行目标弧长」处。

> 这个函数是整个多人群机制的支点：**同一条路径，换个 `targetDist` 就能重截取出另一类人群的边界点**（见 §5）。

### 3.5 多边形与面积（`render` / `Util.polygonArea`）
- 16 边界点 → 多边形（半透明填充 + 中心点标记）。
- 面积用 Snyder 等面积分带法（球面多边形面积），用于报告「可达范围 km²」。

## 4. 路网绕行系数 λ 标定（支撑盲区「步行距离」外推）

等时圈只给出边界，盲区识别需要**任意栅格点到三类 POI 的步行距离**。逐点调路径规划太慢，故用 λ 标定 + 直线距离外推：

```
λ = 真实步行距离 / 直线距离        （路网越绕，λ 越大）

1) 在等时圈内选若干锚点（默认 6）
2) 每个锚点对「最缺类 POI」并发（默认 3）调一次路径规划得真实步行距离
3) 该锚点 λ = walkDist / straightDist
4) 取各锚点 λ 的**中位数**（抗个别绕远异常值），钳制到 [1.0, 1.8]
5) 标定样本 <2 时回落经验值 1.25
```

后续盲区分析对每个栅格点：`步行距离 ≈ 直线距离 × λ`。把「1 次/锚点」的代价降到「常数次级全图标定」，是「少量观测 + 空间外推」思路的工程实现。更细的空间化版本（λ(x,y) 与精度自证）见 `docs/服务盲区识别算法.md`。

## 5. 多人群等时圈（全龄友好）

### 5.1 人群定义
系统内置 5 类出行人群（`config.js` 的 `WALK_TYPES`，面板可逐类修改速度）：

| 人群 | 默认步速 | 折算 | 展示色 |
|---|---:|---|---|
| 成年人（默认主分析人群） | 80 m/min | ≈4.8 km/h | 蓝 |
| 青年人 | 100 m/min | ≈6.0 km/h | 绿 |
| 儿童 | 60 m/min | ≈3.6 km/h | 紫 |
| 老年人 | 50 m/min | ≈3.0 km/h | 橙 |
| 轮椅出行 | 40 m/min | ≈2.4 km/h | 红 |

### 5.2 关键设计：**共享路径，重截断**

一个朴素的做法是为每类人群各跑一遍 16 向路径规划（5 × 16 = 80 次请求），这既慢又费配额。实际做法是：

```
主分析人群一次性采样得到 16 条「完整路径」fullPaths[i]（远达 1800m，超出任何人群的需求）
        │
        ├─ targetDist = 80  × 15 = 1200m → 成年人边界多边形
        ├─ targetDist = 100 × 15 = 1500m → 青年人边界多边形
        ├─ targetDist = 60  × 15 =  900m → 儿童边界多边形
        ├─ targetDist = 50  × 15 =  750m → 老年人边界多边形
        └─ targetDist = 40  × 15 =  600m → 轮椅边界多边形
```

即**同一批真实路网观测，按各类人群的 `速度 × 时长` 重新调用 `Util.pointAtDistance` 截断**，得到各自的真实可达多边形。随后：

- 面积：`Util.polygonArea`
- POI：`pointInPolygon` 逐类过滤出落在该人群多边形内的设施
- 评分：走**与单地址体检完全相同的 `calcScore`**

由此得到的性质很重要：**第 t 类人群的评分 == 把第 t 类人设为主分析人群重新做一次完整体检的分数**。这不是近似，而是口径完全一致，避免了"两套算法给出两个分数"的解释成本。

### 5.3 零额外配额
整个过程不发起任何新的路径规划请求 —— `fullPaths` 是主流程已经拿到的副产品。多人群分析的额外成本只有几万次算术运算。

### 5.4 派生量联动
主分析人群速度与时长的修改会触发统一重算（`recalcDerived`）：

| 派生量 | 计算式 | 默认值（80 m/min × 15 min） |
|---|---|---|
| 采样远点 `farDistance` | 速度 × 时长 × 1.5 | 1800 m |
| 盲区半径 `radiusMeters` | 速度 × 时长 × 5/6 | 1000 m |
| 重度盲区阈值 | 同上 × 1.5 | 1500 m |

> 「15 分钟 → 1000 m」因此是**派生结果而非硬编码**：时长或速度一改，等时圈、盲区阈值、评分口径同步跟随，不会出现"改了时长但阈值没变"的口径撕裂。若用户在设置里手工覆盖了半径/重度阈值，则以手工值为准（标记 `radiusManual` / `severeManual`）。

### 5.5 实测样例
以北京市朝阳区望京 SOHO 为例（同一条真实路网）：

| 人群 | 步速 | 可达面积 | 评分 |
|---|---:|---:|---:|
| 青年人 | 100 | 4.39 km² | 98 |
| 成年人 | 80 | 2.79 km² | 95 |
| 儿童 | 60 | 1.49 km² | 85 |
| 老年人 | 50 | 0.95 km² | 81 |
| 轮椅出行 | 40 | 0.55 km² | 77 |

> 老年人可达面积为成年人的 34%，轮椅出行者仅 20%。这组差异是「适老化 / 无障碍」议题最直观的量化依据，也是单纯看总分会发现不了的结构性信息。

## 6. 算法复杂度与性能

- 路径规划调用次数 = 等时圈 **16** + λ 标定 **≤6** ≈ **22 次/单地址**，靠并发在数秒内完成。
- **多人群分析 +0 次**（共享路径）。
- 全部调用均有超时护栏与降级，最坏情况下退化为「方位角直线等时圈」（仍是合法多边形，仅精度略降），**绝不阻塞主流程**。

## 7. 小结

本算法以「**多方向真实路网采样 + 弧长插值 + 多边形闭合**」为核心，辅以 λ 标定外推，在有限的地图服务调用下逼近真实步行可达区；并通过「**共享路径 + 重截断**」把这一套真实路网观测复用到五类人群上，在零额外配额的前提下给出全龄友好的差异化体检结论。
