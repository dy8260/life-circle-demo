# 等时圈生成算法设计

> 对应任务书「交付要求 #3」之「等时圈生成算法设计（如何基于路网计算可达范围）」一节，以及评审「功能正确性 40% - 可视化展示等时圈热力图」「API 深度调用 - 创新的空间插值」。
> 实现位于 `js/isochrone.js`，配套路网绕行系数 λ 标定位于 `js/gap.js`。

## 1. 目标与定义

**15 分钟步行等时圈**：以用户给定的社区中心点出发，在真实路网下步行 15 分钟（= 80 m/min × 15 min = **1200 m** 理想弧长）所能到达的所有区域的并集，用多边形近似表示。

**为什么不是圆形辐射？**
- 真实路网（封闭小区、河流、立交、单行道）使步行可达区呈不规则形状；
- 圆形辐射要么高估（纳入穿墙/跨河到不了的区域），要么低估（直角绕行被压扁）；
- 多花几秒换来「真实路网」等时圈，对生活圈体检可信度至关重要（`isochrone.js` 头部注释）。

## 2. 算法流程（`Isochrone.build`）

```
输入：中心点 center(BMapGL.Point)，目标时间 15min
参数：sampleCount=16, walkSpeed=80m/min, walkMinutes=15, farDistance=1800m, routeConcurrency=6

1) 方向采样
   for i in 0..sampleCount-1:
       bearing = i × 360/sampleCount        // 每 22.5° 一个方向
       farPt   = Util.destination(center, farDistance, bearing)  // 取 >15min 的远点，留冗余

2) 并发取真实路网路径（核心）
   samples = Util.pmap(directions, _walkOne, routeConcurrency)
       _walkOne(start, end, targetDist=1200, bearing):
           route = new BMapGL.WalkingRoute(map, {renderOptions:{map:null,...}})
           route.search(start, end)          // 起点/终点须是 BMapGL.Point 实例
           取回路径点串 pts（防御式兼容 5 种返回形态）

3) 弧长插值边界点
   boundary = Util.pointAtDistance(pts, targetDist)   // 沿路径累加距离，到 1200m 处线性插值

4) 退化兜底
   若 WalkingRoute 超时(6s)或失败 → boundary = Util.destination(center, targetDist, bearing)
   （按方位角直线远点，保证 16 点始终齐全）

返回：samples（每个方向一个边界点 {lng,lat}）
```

## 3. 关键实现细节

### 3.1 方向采样（`isochrone.js:33`）
- 均匀 16 方向覆盖 360°，每方向独立远点，避免方向偏置。
- 远点取 `farDistance=1800m`（> 1200m 目标），确保路径一定越过 15min 弧长，插值点落在路径中段而非末端。

### 3.2 真实路网路径（`isochrone.js:62` `_walkOne`）
- 调用 `BMapGL.WalkingRoute`，`renderOptions.map=null` 表示只取数据不画线（轻量）。
- **参数分级降级**：部分 GL 版本不接受 `map:null`，故准备两套 `opts` 依次尝试（`isochrone.js:79`）。
- **回调兼容**：除 `onSearchComplete` 外，兼容部分版本只触发 `setSearchCompleteCallback`（`isochrone.js:93`）。
- **6s 超时护栏**：`setTimeout` 到点即退化为直线远点（`isochrone.js:69`），绝不卡死体检。

### 3.3 路径点提取（`extractPath`，`isochrone.js:197`）
百度不同版本取路径的调用链不一致，防御式兼容 5 种：
```
results.getPlan(0).getRoute(0).getPath()      // GL 官方
route.getPlan(0).getRoute(0).getPath()        // 经典 BMap
route.getResults().getPlan(0)...getPath()      // 部分版本
results.getPlan(0).getPath()                   // 简化
route.getPlan(0).getPath()
```
过滤空项并统一为 `{lng,lat}` 字面量，长度 >1 才采用。

### 3.4 弧长插值（`Util.pointAtDistance`，`util.js:48`）
沿路径逐段累加 Haversine 距离，累计达 `targetDist` 时在当前段内按比例线性插值出边界点；全程不足则取末端。保证边界点严格落在「步行 1200m」处。

### 3.5 多边形与面积（`isochrone.js:114` `render` / `Util.polygonArea`）
- 16 边界点 → `BMapGL.Polygon`（半透明蓝填充 + 中心点 pulse SVG marker）。
- 面积用 Snyder 等面积分带法（`util.js:72`，球面多边形面积），用于报告「可达范围 km²」。

## 4. 路网绕行系数 λ 标定（支撑盲区「步行距离」外推）

等时圈只给出边界，盲区识别需要**任意栅格点到三类 POI 的步行距离**。逐点调 `WalkingRoute` 太慢，故用 λ 标定 + 直线距离外推：

```
λ = 真实步行距离 / 直线距离        （路网越绕，λ 越大）

1) 在等时圈内选 calibAnchors=6 个锚点
2) 每个锚点对「最缺类 POI」并发(calibConcurrency=3)调一次 WalkingRoute 得真实步行距离
3) 该锚点 λ = walkDist / straightDist
4) 取 6 个 λ 的**中位数**（抗个别绕远异常值），钳制到 [lambdaMin=1.0, lambdaMax=1.8]
5) 标定样本 <2 时回落经验值 lambdaDefault=1.25
```
后续盲区分析对每个栅格点：`步行距离 ≈ 直线距离 × λ`（`gap.js` `_walkField`），把「1 次/锚点」的代价降到「6 次全图标定」，是「创新的空间插值 / 扇形采样」思路的工程实现。

## 5. 算法复杂度与性能

- WalkingRoute 调用次数 = 等时圈 `16` + λ 标定 `≤6` ≈ **22 次/单地址**，靠 `Util.pmap` 并发在数秒内完成。
- 全部调用均有超时护栏与降级，最坏情况下退化为「方位角直线等时圈」（仍是合法多边形，仅精度略降），**绝不阻塞主流程**。

## 6. 小结

本算法以「**多方向真实路网采样 + 弧长插值 + 多边形闭合**」为核心，辅以 λ 标定外推，在有限 API 调用下逼近真实步行可达区，直接满足任务书「基于路网计算可达范围」与可视化等时圈的全部要求。
