## 一、测试对象与方法

| 项目 | 内容 |
|---|---|
| 测试社区 | 北京市朝阳区（高密度建成社区） |
| 中心点 | 116.4876°E, 40.0026°N |
| 步行参数 | 80 m/min（参照住建部《完整居住社区建设标准》，老年慢节奏） |
| 目标时长 | 15 分钟 |
| 可达圈生成 | 真实步行路网 16 向采样 + 距离场插值（详见 `docs/服务盲区识别算法.md`） |
| 配套类别 | 医院 / 药店 / 菜市场 / 商超 / 学校 / 公交站（6 类，对照配套标准盲区口径） |
| 盲区判定 | 菜市场 / 药店 / 小学 三类步行距离**全部** > 1000 m 的点位（配套标准） |

**方法透明性**：步行距离 = 直线距离 × 路网绕行系数 λ。λ 由 6 个锚点的真实步行路径规划标定
（本社区 λ = 1.40，取自 6 个样本中位数，已按 [1.00, 1.80] 钳制），其余点位用距离场插值外推，
避免对每个栅格点都发起路径规划请求（满足「控制 API 调用次数」要求的工程优化要求）。

## 六、合理性分析与结论

1. **可达面积与评分自洽**：等时圈 2.81 km² → 覆盖 93 分；六类齐全 → 多样性满分；
   完整度 95 分、就近便利度 99 分，综合 97 分属合理区间。
2. **高密度社区无虚警**：全部栅格点均在 1 km 内命中三类基础配套之一，算法返回 0 盲区，证明阈值与口径未过度报警。
3. **λ 标定保证步行距离可信**：λ=1.40 处于合理区间（真实路网通常 1.1~1.5），盲区「1 km 步行」判定未低估绕行。
4. **工程可复现**：全部计算确定性，更换社区/数据后重跑 `node scripts/gen-report-from-snapshot.js` 即得新报告。
