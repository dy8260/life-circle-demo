# 多源 POI 数据清洗策略

> 本文档说明六类民生配套 POI 的检索、去重、过滤与容错设计，以及上游治理不当会如何影响下游的盲区判定与评分。
> 实现位于 `js/poi.js`，分类与阈值配置位于 `js/config.js`。

## 1. 分类体系（多源语义归一）

`config.js` 的 `POI_CATEGORIES` 定义 6 类民生配套，每类含**多个同义关键字**（地图 `LocalSearch` 单 keyword 单结果，需多关键字合并）：

| 类别(key) | 名称 | 关键字（顺序有语义） | 评分权重 |
|---|---|---|---:|
| hospital | 医院 | 综合医院 / 医院 / 社区卫生服务中心 | 0.22 |
| pharmacy | 药店 | 药店 / 药房 | 0.13 |
| market | 菜市场 | 菜市场 / 农贸市场 / 菜店 | 0.15 |
| store | 商超 | 超市 / 便利店 | 0.15 |
| school | 学校 | 小学 / 幼儿园 / 中学 | 0.20 |
| bus | 公交站 | 公交站 / 地铁站 | 0.15 |

**关键设计决策**：
- **菜市场从商超拆出**：盲区判定口径是【菜市场 / 药店 / 学校】。若并入商超，「1 公里内只有便利店」会被误判为「有菜市场」。独立成类保证语义严格。
- **关键字顺序语义**：越靠前越优先被检索；盲区判定关注的三类（菜市场/药店/学校）关键字须排首位，且受 `POI_KEYWORD_LIMIT=3` 截断保护。
  - 术语说明：判定口径原文为「小学」，实现中该类检索关键字扩展为「小学 / 幼儿园 / 中学」，界面与文档统一简称为「学校」。

### 1.1 不同模块消费的子集不同

| 消费方 | 使用的类别 | 说明 |
|---|---|---|
| 盲区识别（`gap.js`） | 菜市场 / 药店 / 学校 | 判定核心三类 |
| 无障碍可达性（`accessibility.js`） | 菜市场 / 药店 / 学校 / 医院 / 公交站 | 共 5 类，不含商超（非刚性公共服务） |
| 补建选址（`recommend.js`） | 菜市场 / 药店 / 学校 | 与盲区口径对齐 |
| 体检评分（`dashboard.js`） | 全部 6 类 | 完整度与多样性评分 |

## 2. 检索与合并去重（`POI.fetchAll`）

### 2.1 检索范围：精确等时圈 + 12% 外扩缓冲
- 先由等时圈 polygon 顶点算 `Bounds`，再 `_expandBounds(b, 0.12)` 向外扩 12%。
- **目的**：等时圈边界上的 POI 因每次 routing 略有差异会时有时无，外扩让它们稳定被搜到；**最终上图前仍用精确 `pointInPolygon` 过滤回真实等时圈**，不改变「显示在圈内」的语义。
- 多人群场景下，外扩还需覆盖「比主分析人群更快」的人群范围，防止快走人群可达范围内的 POI 漏检。

### 2.2 检索节奏：串行 + 间隔 + 提前停止
- 6 类按 `POI_SEARCH_GAP_MS=280ms` 串行间隔检索（规避检索端点并发抖动，尤其对比模式 A+B 连续检索）。
- 每类多关键字合并、按 `uid` 去重；某类召回达 `POI_KEYWORD_STOP_AT=60` 即停剩余同义词，省配额且不损覆盖。
- `LocalSearch` 单 keyword 单页最多返回 `pageCapacity=50` 条且默认只取第一页，稠密区域远超 50 条会被静默截断；开启分页 `POI_MAX_PAGES=2` 后按 `gotoPage` 向后累积，提升召回。

### 2.3 两阶段兜底
- **阶段一空类补 nearby**：仅当本次整体 `globalTotal>0` 时，对个别空类别补一次「中心点周边 `searchNearby`」；全部为空则跳过。
- **整段为空轻量补查**：仅做 1 次短时延迟后的高频词补查；有数据则重检，仍空则判定「确无配套 / 视口错位」。

## 3. 结果提取兼容（多返回形态归一）

`LocalSearch` 不同版本结果结构差异大，`_extract` 做防御式兼容：

1. 优先 `getCurrentNumPois` / `getNumPois` + `getPoi(i)` 取点；
2. 回退到 `EnumerablePois` / `poiList` / `rows` / `pois` / `Pois` 数组形态；
3. 仍为空则 `_deepScan` 递归深扫整个 result 对象，按 `point||latLng + (title||name)` 判定 POI 兜底。

统一输出为 `{ title, address, point:{lng,lat}, uid }`，供渲染 / 热力图 / 报告 / 无障碍分析复用。

## 4. 地图级精确过滤（`POI.render`）

- 上图前用 `pointInPolygon(item.point, polygonPts)` 过滤掉圈外点（射线法），保证「等时圈内配套」语义严格。
- 每类最多显示前 30 个（数量过多影响视觉与性能）。
- 热力图权重按刚需排序：医院 4 > 菜市场 3 > 学校 2 = 药店 2 > 商超 1 = 公交 1。
- 多人群评分会按**各自人群的多边形**重新执行同一套过滤，得到各人群实际可达的 POI 子集。

## 5. 数据质量观察（实测）

这是对当前版本检索结果的诚实披露，也解释了为什么 POI 清洗是持续工作：

| 现象 | 实测样例 | 成因 | 下游影响 |
|---|---|---|---|
| **菜市场类混入餐饮门店** | 某社区「菜市场」类 25 条结果中混入「·江西菜」「·京味家常菜」「江浙菜·烤鸭」等名称含「菜」字的餐厅 | 检索引擎对「菜市场」做文本/分词匹配时，命中了店名含「菜」的餐饮 POI | 虚高菜市场覆盖率 → **低估**该类缺失率 → 可能把真实盲区判为非盲区 |
| **医院类召回偏少** | 同一社区仅检出 2 处 | 「综合医院 / 社区卫生服务中心」等词覆盖面有限 | 完整度评分对医院权重最高（0.22），召回不足会明显拉低总分 |
| **同类 POI 重复出现** | 「果蔬好生活超市」同时出现在菜市场与商超两类 | 不同类别的关键字集存在交叉 | 需依赖 `uid` 去重与类别隔离 |

> 前两条属于**检索引擎侧的行为特征**，本项目已在职责范围内做了 `uid` 去重 + 多边形精确过滤，但**名称层面的语义纠偏尚未实现**（候选改进：按名称/子类目做后置白黑名单过滤，或改用带类目约束的检索方式）。

## 6. 容错与降级（数据质量保障）

| 场景 | 处理 | 位置 |
|---|---|---|
| 地图视口不在检索城市 | `_ensureMapAt` 先把地图中心移到检索点（否则异地恒返回 0） | `poi.js` |
| 地图未就绪 | `_waitMapReady` 上限 ~3s 放行，避免首屏静默空返回 | `poi.js` |
| 真失败（错误码 1/2/3/4/5/101/102/240/302/401） | 按 `RETRY_GAP_MS×i` 退避重试 | `poi.js` |
| 干净返回 0 条 | 判定「该范围确无此配套」，**不**按限流反复重试，仅 1 次短补查 | `poi.js` |
| 命中缓存 | 同 `keyword+bounds` 直接返回非空结果；空结果不缓存 | `poi.js` |
| 三类配套 POI 全缺失 | 跳过盲区分析并提示「无法判定」，不做无意义计算 | `gap.js` |

> **真失败 vs 干净 0 条的区分**是本模块最重要的容错经验：此前把「对比首点全 0」误判为限频而做长退避，实测全败；根因是地图视口/region 错位。修正后干净 0 条不再重试，体检速度大幅提升。

## 7. 数据质量校验（评分口径）

`config.js` 的 `POI_THRESHOLD` 给出每类 `min`（最低门槛）/ `ideal`（理想值）/ `weight`（评分权重），参考住建部《完整居住社区建设标准》与上海《15 分钟社区生活圈规划导则》，用于体检报告的覆盖度评分与达标/缺失分级。

无障碍模块另有独立的服务半径标准（`ACCESS_CATEGORIES`，取自 GB 50180-2018）：菜市场 / 药店 / 学校 / 公交站为 500 m，医院为 1000 m；标准耗时按 `半径 / 80 m/min` 折算（菜市场等 5 分钟类为 6 分钟，医院为 13 分钟）。

## 8. 小结

本策略以「**多关键字合并去重 + 外扩缓冲检索 + 精确多边形过滤 + 多形态兼容提取 + 区分式容错**」组合，把地图 POI 这一「多源、异构、易抖动」的数据源清洗为标准、可信的配套点集，直接支撑盲区识别、无障碍分析、多人群评分与补建选址四项核心功能。

上游召回的偏差会传导到下游判定——因此本模块刻意保持清洗口径透明，并在 §5「数据质量观察」一节如实记录已知偏差，避免使用者误读「零盲区」这类结论。
