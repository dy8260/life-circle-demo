# 多源 POI 数据清洗策略

> 对应项目交付要求 #3 之「多源 POI 数据清洗策略」一节，以及评审「功能正确性 40% - 地图基础能力（POI 检索）」「API 深度调用 - 容错与降级」。
> 实现位于 `js/poi.js`，分类与阈值配置位于 `js/config.js`。

## 1. 分类体系（多源语义归一）

`config.js` 的 `POI_CATEGORIES` 定义 6 类民生配套，每类含**多个同义关键字**（百度 `LocalSearch` 单 keyword 单返回，需多关键字合并）：

| 类别(key) | 名称 | 关键字（顺序有语义） | 权重 |
|---|---|---|---|
| hospital | 医院 | 综合医院 / 医院 / 社区卫生服务中心 | 0.22 |
| pharmacy | 药店 | 药店 / 药房 | 0.13 |
| market | 菜市场 | 菜市场 / 农贸市场 / 菜店 | 0.15 |
| store | 商超 | 超市 / 便利店 | 0.15 |
| school | 学校 | 小学 / 幼儿园 / 中学 | 0.20 |
| bus | 公交站 | 公交站 / 地铁站 | 0.15 |

**关键设计决策**：
- **菜市场从商超拆出**：「15 分钟生活圈」盲区判定口径是【菜市场 / 药店 / 小学】。若并入商超，「1 公里内只有便利店」会被误判为「有菜市场」。独立成类保证语义严格（`config.js:69` 注释）。
- **关键字顺序语义**：越靠前越优先被检索；项目要求的三类（菜市场/药店/小学）关键字须排首位，且受 `POI_KEYWORD_LIMIT=3` 截断保护（`config.js:74`）。

## 2. 检索与合并去重（`POI.fetchAll`）

### 2.1 检索范围：精确等时圈 + 12% 外扩缓冲
- 先由等时圈 polygon 顶点算 `Bounds`（`computeBounds`），再 `_expandBounds(b, 0.12)` 向外扩 12%（`poi.js:47`）。
- **目的**：等时圈边界上的 POI 因每次 routing 略有差异会时有时无，外扩让它们稳定被搜到；**最终上图前仍用精确 `pointInPolygon` 过滤回真实等时圈**，不改变「显示在圈内」语义。

### 2.2 检索节奏：串行 + 间隔 + 提前停止
- 6 类按 `POI_SEARCH_GAP_MS=280ms` 串行间隔检索（规避百度检索端点并发抖动，尤其对比模式 A+B 连续检索）。
- 每类多关键字合并、按 `uid` 去重；某类召回达 `POI_KEYWORD_STOP_AT=10` 即停剩余同义词，**省配额且不损覆盖**（`poi.js:151`）。

### 2.3 两阶段兜底
- **阶段一空类补 nearby**：仅当本次整体 `globalTotal>0` 时，对个别空类别补一次「中心点周边 `searchNearby`」；全部为空则跳过，不再疯狂补请求（`poi.js:181`）。
- **整段为空轻量补查**：仅做 1 次 2s 后高频词补查；有数据则重检，仍空则判定「确无配套 / 视口错位」（`poi.js:212`）。

## 3. 结果提取兼容（多返回形态归一）

百度 `LocalSearch` 不同版本结果结构差异大，`_extract` 做防御式兼容（`poi.js:382`）：

1. 优先 `getCurrentNumPois` / `getNumPois` + `getPoi(i)` 取点；
2. 回退到 `EnumerablePois` / `poiList` / `rows` / `pois` / `Pois` 数组形态；
3. 仍为空则 `_deepScan` 递归深扫整个 result 对象，按 `point||latLng + (title||name)` 判定 POI 兜底。

统一输出为 `{ title, address, point:{lng,lat}, uid }`，供渲染 / 热力图 / 报告复用。

## 4. 地图级精确过滤（`POI.render`）

- 上图前用 `pointInPolygon(item.point, polygonPts)` 过滤掉圈外点（射线法，`poi.js:568`），保证「等时圈内配套」语义严格。
- 每类最多显示前 30 个（数量过多影响视觉与性能）。
- 热力图权重按刚需排序：医院 4 > 菜市场 3 > 学校 2 = 药店 2 > 商超 1 = 公交 1（`poi.js:539`）。

## 5. 容错与降级（数据质量保障）

| 场景 | 处理 | 位置 |
|---|---|---|
| 地图视口不在检索城市 | `_ensureMapAt` 先把地图中心移到检索点（百度按视口中心解析 region，否则异地恒返回 0） | `poi.js:80` |
| 地图未就绪 | `_waitMapReady` 上限 ~3s 放行，避免首屏静默空返回 | `poi.js:247` |
| 真失败（错误码 1/2/3/4/5/101/102/240/302/401） | 按 `RETRY_GAP_MS×i` 退避重试 | `poi.js:353` |
| 干净返回 0 条 | 判定「该范围确无此配套」，**不**按限流反复重试，仅 1 次短补查 | `poi.js:370` |
| 命中缓存 | 同 `keyword+bounds` 直接返回非空结果；空结果不缓存 | `poi.js:16` |

> **真失败 vs 干净 0 条的区分**是本项目最重要的容错经验：此前把「对比首点全 0」误判为限频而做 19s 长退避，实测全败；根因是地图视口/region 错位。修复 `_ensureMapAt` 后，干净 0 条不再重试，体检速度大幅提升（`poi.js` 头部注释与 `config.js:49` 注释）。

## 6. 数据质量校验（评分口径）

`config.js` 的 `POI_THRESHOLD` 给出每类 `min`（最低门槛）/ `ideal`（理想值）/ `weight`（评分权重），参考住建部《完整居住社区建设标准》与上海《15 分钟社区生活圈规划导则》，用于体检报告的覆盖度评分与达标/缺失分级。

## 7. 小结

本策略以「**多关键字合并去重 + 外扩缓冲检索 + 精确多边形过滤 + 多形态兼容提取 + 区分式容错**」组合，把百度 POI 这一「多源、异构、易抖动」的数据源清洗为标准、可信的配套点集，直接支撑盲区识别与体检评分两项核心功能。
