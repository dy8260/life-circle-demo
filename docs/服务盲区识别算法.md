# 服务盲区识别算法（Service Blind-spot Identification）

> 判定问题：给定一个社区中心，**能否准确找出周边 1 公里内到菜市场、药店、小学都不可达的「服务盲区」点位**？
>
> 术语说明：判定口径原文为「小学」；实现中该类检索关键字扩展为「小学 / 幼儿园 / 中学」，界面与文档统一简称为「学校」。

本模块代码位于 `js/gap.js`（`GapFinder`），在看板、地图、体检报告三处消费其结果。
在其之上还有两个只读消费层：
- `js/stress.js`（应力测试）：把同一次分析再向下挖一层——区分「直线看着有、实际走不到」、测算临界步速、归因缺口成因；
- `js/recommend.js`（补建选址）：把缺口点转成可执行的设施落点建议。

---

## 1. 问题定义与判定口径

- **判定对象**：15 分钟步行等时圈（真实路网多边形）内部的所有居民点位。
- **盲区定义**：某一待判定点，到 **菜市场 / 药店 / 学校** 三类的**步行距离全部 > 1 km** → 该点即服务盲区点位。
  - 取三类里「最容易到达的那一类」的步行距离（记为 `worst`）作为该点的「缺口强度」：`worst > 1000m` 即判定为盲区。
  - 重度盲区：`worst > 1500m`。
- **为什么用步行距离而非直线距离**：生活圈语境下的「周边 1 公里」指**步行可达 1 公里**。直线距离会系统性高估可达性——绕行、过街天桥、封闭小区、断头路都会拉长实际路程。本算法以「直线距离 × 路网绕行系数 λ」外推步行距离。

## 2. 算法主干（五步）

```
等时圈多边形 ──①栅格采样──▶ 分析栅格点集合
                              │
        POI(菜市场/药店/学校) ─┤ ②λ标定（抽锚点调真实 WalkingRoute）
                              │
                   ③距离场插值（直线×λ 外推全域步行距离）
                              │
                   ④盲区判定（三类步行距离全>1km）
                              │
                   ⑤连通斑块聚合（4邻域连通分量 → Top-N 斑块）
```

### ① 栅格采样
在等时圈多边形的 bounding box 内按 `gridStepMeters`（默认 120 m）打正交栅格，射线法（`pointInPolygon`）只保留多边形内的点。
- **点数守卫**：预估点数过大时自动放大步长，防止超大等时圈卡死浏览器。结果会标记 `stepAutoEnlarged`。

### ② λ 标定（路网绕行系数）
λ = 真实步行距离 / 直线距离。
- **锚点选取**：判定边界在「直线距离 ≈ 1000 / λ ≈ 800 m」附近，此处的 λ 准确性影响最大。故先按 `|d_straight − target|` 升序圈出候选池，再用**最远点采样（FPS）**挑出空间上尽量分散的 N 个锚点（默认 6 个），兼顾「贴近判定边界」与「覆盖不同方位」。
- **并发**：对锚点并发调用地图 `WalkingRoute`（默认 3 并发，复用 `Util.pmap` 限流）。
- **聚合**：取各锚点 λ 的**中位数**（抗异常值：个别锚点绕远路 λ 可飙到 2.7+，但中位数不受绑架）。
- **钳制**：`λ ∈ [1.00, 1.80]`。
- **兜底**：样本 < 2 条 → 退回经验值 `λ=1.25`，并标记 `lambdaFallback=true`。

### ③ 距离场插值（零额外 API）
对每个栅格点求其到各类 POI 的**直线最近距离**（带网格空间索引加速），再 `步行距离 = 直线距离 × λ`。
这是关键的工程取舍：用少量真实路网观测（6 次）外推全域，而不是对每个栅格点都发一次路径规划请求。

### ④ 盲区判定
`worst[i] = min(三类步行距离)`，若 `worst[i] > radiusMeters` → 盲区点；按 `worst[i]` 分「一般 / 重度」两级。同时统计每类单独超阈值的栅格占比（`missingRate`）。

### ⑤ 连通斑块聚合
对盲区点做**栅格 4 邻域连通分量**分析，聚成「连片盲区斑块」；单点噪声（< 3 格）丢弃。每个斑块计算质心、面积、平均/最大缺口强度，**严重度 = 面积 × 平均缺口强度**，降序取 Top-3 作为「优先改造斑块」。

**主判定稳定性说明**：以上五步始终使用**单一全局 λ**。后文的 λ 空间场是**加法式扩展**，不介入这条既有判定路径，保证 `gapCount` 的结果在任何情况下都不因 space场而漂移。

## 3. 三态盲区（看得见的 vs 走得到的）

「是否盲区」是一个二值结论，但它掩盖了一个重要差异：有的地方**画圆看着有配套**，实际步行根本到不了；有的地方**连直线都够不着**。为此每个栅格点被划分为三态（`js/gap.js:1034`：

| 状态 | 值 | 判定条件 | 语义 |
|---|---|---|---|
| 覆盖 `cover` | 0 | `mnWalk ≤ R` | 最近的一类步行可达，正常覆盖 |
| **隐性盲区** `hidden` | 1 | `mnWalk > R` 且 `mnStraight ≤ R` | 直线口径判定为「有配套」，实际步行超阈值——**正是纯直线分析法会漏判的那一批** |
| **显性盲区** `explicit` | 2 | `mnWalk > R` 且 `mnStraight > R` | 直线距离本身就已经超标，任何口径都会检出 |

其中 `mnWalk = min(三类步行距离)`、`mnStraight = min(三类直线距离)`，`R = radiusMeters`（默认 1000）。

**这一分类的实践价值**：`hiddenRatio` 直接量化了「如果改用直线距离，会漏判多少」。河网密布、封闭小区多的社区，隐性占比会显著高于规整方格路网的社区。

### 3.1 置信度
λ 是稀疏抽样标定的，离观测点越远越不可信。为此对每个点的判定附一个置信度：

```
conf[i] = clamp(1 − dmin / Rconf, 0.15, 1)
Rconf   = clamp(观测点两两最大距离 × 0.5, 600, 3000)
```

- `dmin` = 该点到**最近观测点**的距离；`Rconf` 由观测点的空间展布自适应得出。
- 输出 `confMean`（参与判定的非覆盖点的平均置信度）与 `lowConfidenceRatio`（`conf < 0.4` 的点占比）。
- **低置信比率偏高时，应把结论当作「待实地复核的线索」而非定论**。这是本算法主动暴露自身不确定性的地方。

## 4. λ 空间场 λ(x,y)：从单一常数到空间异质

单一全局 λ 隐含一个假设：这片区域各方向的绕行程度差不多。河流分割、铁路阻隔、大面积封闭小区都会打破这个假设。因此在主判定之外，额外构建一张随位置变化的 λ 场（`js/gap.js:885`）：

### 4.1 观测点来源
共两类（见 `_collectObservations`）：
1. **λ 标定锚点**（标记 `from:'calib'`，默认 6 个）；
2. **无障碍分析的真实路况样本**（标记 `from:'access'`）：`js/accessibility.js` 在实测时会回灌一批 `lambdaPairs`，且只保留 `src === 'route'`（确为真实路径规划所得）且直线距离 ≥ 60 m 的样本，避免近邻抖动样本污染插值。

> 回灌入口是 `GapFinder.refineLambdaField(pairs)`，由 `app.js` 在无障碍分析完成后调用。
> 它**只刷新 `lambdaField` 与 `tristate`，不改动 `gapCount`** —— 即"补精度"与"定结论"在数据流上是解耦的。

### 4.2 插值与置信衰减
采用**反距离加权（IDW，幂次 2）**，无搜索半径截断：

```
w_j = 1 / d_j²
λ(x,y) = Σ(w_j · λ_j) / Σ w_j      然后 clamp 到 [1.00, 1.80]
```

观测点少于 2 个时，全场退化为全局常数 λ，且置信度一律置为下限 0.15。

### 4.3 输出字段
| 字段 | 含义 |
|---|---|
| `globalLambda` | 参与主判定的全局 λ（标定中位数） |
| `observationCount` | 有效观测点数量 |
| `range.{min,max,mean}` | 观测 λ 的分布，直观反映路网绕行是否剧烈 |
| `topDetours[]` | λ 最大的前 3 个观测点（含直线/实走/绕行增量），用于定位「最该打通的地方」 |
| `confMean` | 全场平均置信度 |

## 5. LOOCV 精度自证（以及为什么结果可能为负）

有了插值模型，就必须回答：**空间插值真的比「全图一个常数」准吗？** 用留一交叉验证（LOOCV）回答（`js/gap.js:968`）：

逐个剔除第 i 个观测点，用剩余点插值预测它的 λ，与实测值比对。基线模型是「其余观测 λ 的算术均值」，即代表"什么都不做、用一个常数"的效果。

| 指标 | 含义 |
|---|---|
| `mae` / `rmse` | 空间场的平均绝对误差 / 均方根误差 |
| `maeBaseline` / `rmseBaseline` | 基线（全局常数）的对应误差 |
| `improveMae` / `improveRmse` | 相对改进率，`(基线 − 空间场) / 基线` |
| `r2` | `1 − SS_res / SS_tot`（内部保留，不作为对外结论） |

**为什么会出现负值？** 观测点很少（初始只有 6 个标定锚点）时，IDW(1/d²) 会被最近的那个观测点主导，方差被放大，预测误差可能**反高于**直接猜一个全局均值。此时 `improve*` 为负、`r2 < 0`，这是对模型当前不可靠的**诚实信号**，不是 bug。

**有正面意义的条件**：观测点数量上来（无障碍样本回灌后常多一个数量级）、空间分布分散、且 λ 确实存在区域性差异时，`mae < maeBaseline` 且 `r2 > 0` 才成立。因此本模块把 LOOCV 作为**可复现的透明度指标**输出，并明确规定：**精度自证未通过不影响主判定结果，也不对外渲染为"精确"承诺**。

## 6. 可达性塌缩曲线与临界步速

`js/stress.js` 把同一批实测距离按不同步速重算，回答一个问题：**这个世界对"走得多慢的人"开始失效？**

- **输入**：无障碍分析实测的 `dist`（真实步行距离）与各类别标准耗时 `stdMinutes`。
- **扫描**：步速 40 → 120 m/min，步长 5，共 **17 档**。
- **达标率**：`rate_c(v) = |{点 p : dist_p / v ≤ stdMinutes_c}| / N_c`
- **临界步速 Vc**：沿步速升序取**第一个使达标率 ≥ 60%** 的步速，即"让某类设施达到基本可达所需的最低步速"。全程不达标记为 `>120`。
- **`mostFragile`**：Vc 最高的那一类设施，即"最不禁得起慢下来"的短板。

> 全程纯算术，不重新生成等时圈、不调用任何地图服务。

## 7. 步行阻抗场可视化

把 §4 的 λ(x,y) 画成热力图（`js/stress.js`： `_renderImpedance` / `showImpedanceLayer` / `_drawImpedance`）：

- 归一化 `t = (λ − min) / (max − min)`，**色相 `hue = 210° × (1 − t)`**（蓝 → 红，红=绕行剧烈）；
- **透明度 `alpha = 0.2 + conf × 0.45`**：置信度越低画得越淡，让"不可靠区域"在视觉上自动弱化；
- 点数超过 1600 时按 stride 抽样，用 Canvas 覆盖层一次性绘制；
- 同一张图上并列展示 §5 的 LOOCV 指标（含与基线的对比和改进率），让"这张图值不值得信"自证于图上。

## 8. 缺设施 / 缺路归因决策树

发现缺口后，下一步是判断**该新建设施，还是该打通道路**。`js/stress.js:833` 的归因逻辑按以下顺序分叉（阈值 `threshold = 主分析人群步速 × 标准耗时`）：

```
对每个未达标的（抽样点, 类别）：
  1) dist ≤ threshold                  → 达标，不参与
  2) 缺少直线距离数据（保守处理）      → 记为「供给缺口」
  3) straight > threshold              → 「供给缺口」  ← 设施本身太远，只能新建
  4) 其余（直线够得着、走不过去）      → 「连通缺口」  ← 路的问题，loss = dist − straight
```

输出与实践含义：
- **连通缺口**按 `最近设施` 聚合成「打通清单」，取累计绕行损失 Top-5，`loss` 越大越优先打通。
- **行动建议**按累计损失分三档（≥ 600 m / ≥ 300 m / 其他）。
- **总体结论**按 `connectRatio`（连通缺口占比）分三档：≥60% → 以打通为主；≥30% → 两类并行；其余 → 以新建为主。

> 这条归因把「该找市政还是该找规划」的决策前置到了体检结果里，避免了所有问题都被简化成"再建一个设施"。

## 9. 补建选址建议（`js/recommend.js`）

对仍有缺口的类别，输出可直接落地的设施点位：

- **输入**：仅依赖 `gapResult`（需求点由 `_walk` / `_isGap` / `gapPoints` 派生），不依赖无障碍模块。
- **需求点构造**（两源合并）：
  1. 三类全缺的重度盲区点，权重 `w = worst`（缺口强度）；
  2. 单类超阈值的栅格点（排除已计入盲区的点，避免重复），权重 `w = max(1, d/R)`；
  3. 需求点超过 300 个时等距抽样，控制求解规模。
- **贪心选址**：每轮以剩余需求点为候选，覆盖判定 `distance(候选, 需求点) ≤ R`，目标函数 `score = Σ w`（按严重度加权）；取分最高者，落点取**被覆盖需求点的加权质心**；移除已覆盖点后进入下一轮，直到取满 `topK`（默认 3）或无剩余需求。
- **输出**：`totalUncovered`（该类需求点总数）、`sites[]`（含 `covered` 覆盖点数、`coveredPct`、`rank`）、`eliminatedPct`（累计消除比例）。
- **两档文案**：算法本身无分支，始终合并两源；仅结论文案区分「已识别 N 处三类全缺重度盲区」与「暂无重度盲区，以下为单类局部缺口建议」。所有类别均无需求点时返回不可用。
- **零配额消耗**：全程直线距离计算，无网络请求。

## 10. 工程优化

| 优化点 | 做法 |
|---|---|
| **空间索引** | 对每类 POI 建网格哈希（`IDX_CELL_DEG≈440m`），最近邻用「环形扩散 + 剪枝」，避免 O(栅格×POI) 全量计算；POI 数 ≤ 40 时直接暴力（省一次 Map 开销）。 |
| **API 次数控制** | 盲区分析全程只花 `calibAnchors`（默认 6）次 `WalkingRoute` 做 λ 标定，其余全部空间插值，相比「每栅格一次路径规划」省下 2~3 个数量级调用。 |
| **并发限流** | `Util.pmap(arr, fn, concurrency)` 统一并发，锚点标定默认 3 并发，避免触发地图服务 QPS 限制。 |
| **超时降级** | 单次标定 6s 超时即视为失败（该锚点不参与标定），不影响整体。 |
| **点数守卫** | 超大等时圈自动放大栅格步长，防止主线程长时间阻塞。 |
| **渲染性能** | 盲区点（动辄数百上千）用 Canvas 覆盖层一次性绘制，而非给每个点创建矢量对象；仅 Top-3 斑块用矢量 Label。随地图平移/缩放实时重投影。 |
| **确定性** | 算法主体无随机性（FPS 锚点选取为确定性贪心），同输入两次运行结果完全一致，便于回归验证。 |
| **零配额扩展层** | 应力测试四模块与补建选址均为纯离线计算，不新增任何地图请求。 |

**关于批量距离矩阵**：浏览器端 AK 调用地图 Web 服务 Batch 距离接口通常被服务禁用，因此本算法采用明确可行的等价路径——少量并发路网请求 + 空间插值外推，既把调用次数压到常数级，又在过程中对自身精度做定量自证。

## 11. 输入 / 输出契约

**输入**（`GapFinder.analyze(center, polygonPts, resultByKey, onProgress)`）
- `center`：体检中心点 `{lng, lat}`
- `polygonPts`：等时圈多边形顶点数组（来自 `Isochrone.build`）
- `resultByKey`：`POI.fetchAll` 的返回值，至少含 `market / pharmacy / school` 三类的 `items`
- `onProgress(p, msg)`：进度回调

**输出**（核心字段）
- `enabled` / `ok`：是否成功
- `gridCount` / `gapCount` / `severeCount` / `gapRatio` / `gapAreaM2`
- `lambda` / `lambdaRaw` / `lambdaFallback` / `lambdaClamped` / `lambdaSamples` / `lambdaDetail`：λ 标定透明度
- **`tristate`**：`counts{cover,hidden,explicit}`、`hiddenRatio`、`explicitRatio`、`confMean`、`lowConfidenceRatio`
- **`lambdaField`**：`globalLambda`、`observationCount`、`range`、`confMean`、`topDetours`、`loocv{n,mae,rmse,maeBaseline,rmseBaseline,r2,improveMae,improveRmse,meanLambda}`
- `gapPoints[]`：盲区点位明细（三类距离 / 缺口强度 / 瓶颈类）
- `patches[]`：Top-N 连片斑块（质心 / 面积 / 严重度）
- `centerStatus`：中心点自身的盲区状态（一句话结论）
- `missingRate` / `bottleneckCount` / `poiCount`：各类缺失率、卡脖子统计、参与 POI 数
- `_grid/_walk/_isGap/_level/_worst/_keys`：渲染与调试内部引用

**精化接口**（`GapFinder.refineLambdaField(pairs)`）：只刷新 `lambdaField` 与 `tristate`。

## 12. 已知边界

1. **主判定用全局 λ**：粗糙但稳定，在路网各向异性极强的区域（河流分割）会引入局部误差。已通过重度阈值 500 m 缓冲、连通聚合降噪，以及独立的 λ 空间场做补充评估三层缓解。
2. **LOOCV 可能为负**：观测稀疏时的预期表现，不代表主判定失效，仅说明此时空间场不宜单独作为结论依据。
3. **依赖 POI 检索召回率**：某类 POI 若被检索漏检，会虚高该类缺失率。
4. **三态判定依赖全局 λ**：`hidden` / `explicit` 的划分使用的是 λ 外推的步行距离，λ 场只提供置信度。
5. **置信度阈值硬编码**：低置信阈值 0.4、置信下限 0.15、IDW 幂次 2、置信半径 [600, 3000] 目前写死在实现内，未开放为可调配置项。
